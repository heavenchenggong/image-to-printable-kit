# Parametric Printable Models (Multicolor / AMS)

## First decision: parametric modeling or AI image-to-3D

**Do not default to AI image-to-3D.** The only criterion: can the shape be described parametrically?

| Subject | Route | Reason |
|---|---|---|
| Robots, mascots, snowmen, letters, logos, geometric decor built from spheres/capsules/cylinders | **Parametric modeling (this skill)** | AI invents the back of a flat vector image wholesale — spheres deform, symmetry drifts, part positions wander. Parametric is faster, more accurate, and watertight by construction |
| Fur, folds, organic surfaces, faces, figure-grade detail | AI image-to-3D (Meshy / Hi3D / MakerLab) | These can't be parameterized; AI reconstruction is the only option |

If the user already said "I want it printable", route per the table above and **don't ask for requirements first** — give the verdict and the reason.

## First decision: AMS single-piece / glued multi-part / glue-free snap-fit

These are **three independent routes**, not three names for one thing. "Color-split" = middle column;
"glue-free / snap-fit / assemble-disassemble / no glue" = right column. If the user doesn't specify,
**default to routing by "AMS or not"**, and mention in the delivery notes that the other two variants exist.

| | AMS single-piece | Glued multi-part | Glue-free snap-fit |
|---|---|---|---|
| Form | One piece, in-layer color changes | N independent parts, glued after printing | N independent parts, press to assemble |
| Needs AMS | Yes | No | No |
| Consumables | Self-weight + purge | Self-weight + joint material | Self-weight + joint material |
| Repeated assembly | — | No | **Yes, and ball joints stay angle-adjustable after assembly** |
| Print orientation | One orientation for the whole | Per-part optimum | Per-part optimum |

> ⚠️ **You cannot "split by color into N parts"**: a color's shell is often a dozen-plus disconnected fragments;
> split that way you get scrap full of overhang islands. **A part is one connected printable solid (color is just an attribute).**
> Chunk by geometry first, then assign colors; allow recoloring a small chunk to merge parts when needed.
>
> ⚠️ **The color-split deliverable is "plates", not one file**: after splitting, export **one plate per color**,
> one color per plate, every object on each plate locked to slot 1 (`splitter.write_colour_plates()`). Laying several colors
> on one bed gives back everything color-split bought you — the wipe tower returns, every color change purges
> (small parts' changeover waste often outweighs the part itself), and dual-nozzle machines will **refuse to slice**
> when the two spools have different temperature classes ("printing high-temperature and low-temperature materials simultaneously may clog the nozzle or damage the printer"). Keep the mixed-color single-plate version only as a layout
> reference, and write in the delivery notes "do not print this one".

The four red lines for splitting, the joint dimension table, and the acceptance checklist are in `references/split-to-print.md`
(helper `scripts/splitter.py`); glue-free joints (the four ball-joint numbers, **why press pegs need slide fit + bead catch**,
the four geometric red lines, insert/pull sweep validation) are in `references/snap-fit.md` (helper `scripts/joints.py`).

## Workflow

1. **Read the reference image, decide the primitive decomposition.** Annotate on the image: which chunk is a sphere, which a capsule, which a cone, and their relative proportions. Front view only? Fill in the back in the most plausible way (and state in the delivery notes which part is inference).
2. **Get real color values**, don't eyeball. Use PIL `quantize(colors=8, method=MEDIANCUT)` to extract the dominant palette, take the highest-frequency buckets.
3. **Write the modeling script** (using the `scripts/ptools.py` helpers). All dimensions as top-level constants, pose as explicit coordinates — the user changes one number and gets a new revision.
4. **Split shells by color**, not parts into files. The real unit of AMS printing is "color": one color = one shell = one object = one AMS slot.
5. **Export 3MF** (`scripts/threemf.py`) with embedded basematerials color values. Export STL as backup too.
6. **Render a four-view preview** (`scripts/preview.py`), self-check silhouettes against the reference, adjust proportions, re-run. **You must look at the image, not just bbox numbers.**
7. **Run the printability checklist**: `references/printability-checklist.md`. **Plus the pre-slice gate**: `warp.py out.3mf`. It asks two things — **will it warp** (`lift = span²/depth`) and **will it stand** (margin from `COM` center of mass to the ground footprint). Any part judged `redesign` means **go back and change the model or the pose** (remove non-load-bearing base plates / break long edges / thicken / chamfer; if COM is outside, re-pose with `splitter.rest_flat`) — do not tweak slicer settings. See `references/warp.md`.
8. **Color-split route**: per part check connectivity (`n_components`, welded by coordinates) and watertightness; rotate each part to its own optimal orientation; run `footprint` to confirm COM falls inside the ground convex hull.
9. **Export per-color plates** (mandatory on the color-split route): `splitter.write_colour_plates(plate, out_dir, stem=..., names={hex: slug}, merge={drop: keep})` — splits into N **single-slot** files by color, re-packs each plate; look at bed occupancy first, then decide `merge`. `merge` folds "colors with only one part" into another plate: don't give a single eye piece its own plate.
10. **Glue-free route**: first `joints.check()` to verify strain/interference, then produce **fit coupons** (5 collars + 2 ball pins) so the user can print and confirm interference, **then produce the full set**. Also run an insert/pull sweep once (see `references/snap-fit.md` "Verification"). Coupons are always **single-color** — shape already distinguishes socket from pin, and single-color lets you print them in scrap filament.
11. **Weighing**: before reporting any weight, run `weigh_3mf.py` (seconds per plate with presets). Numbers in the plate table must be **slicer-measured**, with the basis stated (**machine / process / filament preset names** + layer height / wall count / infill / **density**). **Resolve density from the preset chain, don't hand-write it** — `--material PETG` also switches to the real PETG preset; PETG Basic is **1.25**, not the category value 1.27. Mesh estimates from script self-tests may only be labeled `est.` and must not enter the delivery table.
12. **Bake (mandatory before delivery, or the user will ask "why the popup")**: one call to `bake_project.py` turns the pure-geometry 3MF into **a project file as if saved by the slicer itself** — adds `Metadata/project_settings.config`, gcode, thumbnails, and pins `close_fan_the_first_x_layers=3` (default is **1**, fan kicks in on layer 2), `curr_bed_type`, `filament_type`/`filament_density`. See `references/delivery.md`.
13. **Delivery README**: file list, **plate table (which plate has which parts / bed occupancy / slicer-measured weight)**, color table, slice settings, minimum scale, assembly order, known tradeoffs, copyright.


## Key engineering conventions

### Booleans are your friend; overlap is not
Primitives may interpenetrate, but **within one color shell** everything must be boolean-`union`ed into a watertight solid. Two different color shells may overlap each other — but **never as "a 0.7 mm membrane wrapped around another solid"**: in the slicer that's a standalone thin wall that snaps off at a touch.

The correct approach is to cut both shells **at the same seam**: give the sphere `intersection(sphere, halfspace(z_lo=seam-0.3))` and `intersection(sphere, halfspace(z_hi=seam))`, so the seam overlaps by only 0.3 mm.

### Color-change seams should land on horizontal planes
When color is assigned per object, color changes happen only at whole-layer boundaries → minimal purge. Slanted seams or per-layer interleaving explode the number of color changes.

### Pose serves printing
Support-free poses: arms down, splayed <30°, no downward-facing planes. Dynamic poses need supports — say so explicitly (aux nozzle + Support for PLA, tears off clean); don't uglify the model just to avoid supports.

### Floating designs must touch ground
Mascots designed to float (ripples underfoot, no legs) need a base or color-split, or they can neither print nor stand.

## Scripts

- `scripts/ptools.py` — `vec` / `frame` / `place(oriented)` / `union` / `chain_capsules(tube with graduated thickness along a polyline; horns, fingers)` / `bezier` / `halfspace` / `cn(cone, already centered)` / `frustum(frustum; 45° shoulders and chamfers)` / `chamfered_base(cylinder with a 45° base chamfer)`
- `scripts/threemf.py` — `write_3mf(shells, out, filaments=[(label, hex), ...])`. Builds the 3MF from scratch: `<basematerials>` + one `<object>` per color, **plus `Metadata/model_settings.config`** (object names + filament slot numbers) — `basematerials` does nothing in Bambu Studio; that config is the only way the slicer shows correct names and slots. `filaments` is the **delivery contract**: it fixes slot order, and the user must load filament in that order.
- `scripts/preview.py` — multi-view orthographic preview. `views=[(name, azim[, elev])]`; use `elev≈74` for a top-down look at flat parts.
- `scripts/splitter.py` — color-split toolbox: `slab` (cut assembly planes) / `cyl_d` (specify pins and holes as "20→32 mm along a direction") / `n_components` (connectivity welded by coordinates) / `footprint` (ground area + is COM inside the ground convex hull) / `footing_margin` (**signed margin from COM to the ground outline; negative = it tips over**) / `overhang_area` (downward-facing overhang area ≈ support volume) / `lay_flat` (lay it down; auto-**falls back** to `rest_flat` when it can't stand or ground contact is below `MIN_CONTACT`=5 mm²) / `rest_flat` (**searches the convex-hull faces for the true resting pose**; "is a face touching the plate" is judged with `CONTACT_TOL`=0.10 mm, "is COM off-center" with 0.6 mm — **don't mix the two rulers**) / `upright` / **`orient(spec="face", dirvec)`** (entry point when the slicer's verdict picks the orientation; `dirvec` = **the direction that should touch the bed, an increment stacked on top of `lay_flat`** — candidates are judged on the **already-exported print-pose STL**; treating it as an absolute frame direction **rotates twice**) / `mirror_twin` / `write_kit` (pack + export) / `write_colour_plates` (**split by color into N single-slot 3MFs**: `merge={drop: keep}` merges colors, `names={hex: slug}` names files, returns per-plate part count / bed occupancy / estimated weight)
- `scripts/joints.py` — glue-free joints: `ball_pin` (**slotted elastic chuck**, `bury` = buried section inside the host part) / `ball_socket` (rigid ball cavity, mouth auto-cut outward 1 mm) / `press_peg` / `press_hole` / **`bead_peg` + `bead_hole`** (slide-fit body + elastic bead catch on the male side, **the correct form of the press peg**; `bead_peg` returns `(add, cut)`, the slots must be subtracted after the union) / `bead_strain` (leaf strain check, < 2 %) / `snap_skirt` / `boss_groove` / `taper_pin` / `check` / constants `JOINT_S` `JOINT_XS` `JOINT_XXS`. ⚠️ **`press_hole`'s negative clearance is "jams solid" in real hardware, not "press fit"** — see "Press pegs: don't use interference" in `references/snap-fit.md`.
- `scripts/mate_profile.py` — **run before assembly (the third gate for bead/press joints)**: takes `joints.bead_peg` / `bead_hole` and measures four things along the axis — **body clearance** (can the body actually slide in), **bead grip** (enough interference), **axial margin** (will the pin bottom out first), **leaf strain**. The first two are radial; **the third is the real killer**: the winston incident — "arm wouldn't go in at all, had to cut the pin off" — was a Ø5.60 pin driven into a Ø5.30 hole with the end face bottoming out — **a joint that bottoms out won't close no matter how loose it is**, and in CAD it's completely invisible. `python -m scripts.mate_profile`; exit code works as a gate. (Hard-won lesson: boolean solids carry T-junctions; section coordinates must be `np.round(...,4)` before the loop closes, else `polygonize` returns 0 polygons and every reading is `nan`.)
- `scripts/test_joints.py` — mandatory after any change to `joints.py`: compute strain, check watertightness, **cut a section to confirm the chuck really has 4 leaves**, measure actual press-fit interference. `ALL PASS` or it doesn't count.
- `scripts/warp.py` — **mandatory before slicing**: measures three numbers of the ground face (`contact` area / `span` longest continuous run / `depth` = part volume ÷ contact area), computes **`lift = span²/depth`**, bands into `ok | brim | redesign`; **also reports `COM`** (margin from center of mass to the ground outline; negative = it tips over on its own). Exit codes work as a gate (ok 0 / brim 1 / redesign 2). **Nine out of ten warping problems are geometry problems — read this before touching slicer settings.**
- `scripts/overhang.py` — **mandatory before slicing (pairs with warp.py)**: catches **a horizontal step around the part's midsection**. `warp.py` only sees the first layer, the slicer only sees fully detached islands, **and the third failure class in between belongs to nobody**: the step connects to material above and below, the slicer raises no alarm, it's not the first layer, but below that ring is air and the first few layers extrude into the void. Measured on winston P2 `01 base+lower body`: at z=21.0 the diameter jumped from Ø28 straight to Ø36 (**+4.035 mm radius in a single layer / 406 mm²**), the slicer said "no warnings", the physical part had a blob of spaghetti at the neck. Criteria: for watertight meshes use real-section `area` (newly exposed overhang area) + `span` (how far to the nearest material below = the true overhang reach); if not closed, fall back to area-only `Δr` (equivalent-radius single-layer growth) / `ΔA`. Exit codes 0/2 work as a gate. ⚠️ It **must not** use a convex hull — the hull bridges the two limbs of a bent part (measured on an arm: hull reported 101.8 mm²/7.04 mm, the real number was 0.01 mm/layer); and you **must** pass an explicit `plane_transform` to `Path3D.to_2D()`, otherwise every layer gets a different coordinate frame. **Fix**: turn the step into a **45° shoulder** built with `ptools.frustum()` (both ends of the frustum must be buried into the adjacent solids; don't let end faces land on surfaces).
- `scripts/audit_3mf.py` — **mandatory before delivery**: per object, "is this one watertight printable solid". Parses `3D/3dmodel.model`'s vertices/indices itself and builds `Trimesh(process=False)` (**do not use `trimesh.load()`** — the load path repairs meshes, so good parts get flagged as scattered). Exit code works as a gate.
- `scripts/pose_brute.py` — **run when the print orientation is undecided**: ranks 200–300 candidate poses offline (real first-layer section + floating volume "connected over ≥2 layers"), then **feeds each to the slicer for a verdict** (`result.json → sliced_plates[0].warning_message`; empty string = clean). Slicing one 45 mm part costs **1.4 s**; 8-way parallel finishes in about a minute. Verdicts are usually **bimodal**: a passable pose exists → write it into the part definition with `orient("face", dir)`; **none pass** → stop searching and give **that one part** object-level tree supports. ⚠️ **`footprint()` is a proxy, not a verdict**: on concave undersides it's **wrong in both directions** (measured: horn 153→18.4 mm², 8× too high; ear fin 1→4.35 mm², 4× too low). **Too high is the dangerous one** — it grades a "balance-on-a-knife-edge" pose as "standing fine", making the `MIN_CONTACT` gate a rubber stamp. Details in `references/split-to-print.md`.
- `scripts/presets.py` — **the single implementation of preset resolution**, shared by `weigh_3mf.py` and `bake_project.py` (otherwise "the basis at bake time" and "the basis at weigh time" drift; measured drift was 5%): `find_preset(kind, stem, prefer=...)` (**scores substring hits to pick the nearest match**, otherwise you land on files like `Bambu PETG Basic @BBL A1 0.2 nozzle` with the wrong nozzle) / `flatten_preset` (**merges ancestor→child layer by layer, child wins** — this is what gets the CLI the correct bed temperature) / `resolve_filament` (walks the chain for `filament_type` and density) / `write_presets` (writes the machine / process / filament chains as flattened copies) / `preset_args` / `read_result_error` (reads `result.json`; **judge by `return_code`, not `error_string`**).
- `scripts/weigh_3mf.py` — **mandatory before reporting weight**: calls the Bambu engine to slice, sums the gcode E values to get **true** extruded volume and weight. ⚠️ **`--slice` must come with `--load-settings "<machine>;<process>"` + `--load-filaments "<filament>"`**, otherwise it hangs forever at `Initializing StaticPrintConfigs`: no error, no gcode, exit code 0, process won't exit. **That log line is easily misdiagnosed as "the GUI holds the single-instance lock" — the GUI was long gone and it still hung; the real culprit is the missing presets** (we burned two 5-minute waits on this). Density **resolves along the preset `inherits` chain** (PETG Basic 1.25 / PLA Basic 1.26, neither is the category value); `--material` picks the right preset as a side effect; `--density` / `--filament` / `--printer` / `--process` can override. **Never report weight as mesh volume × factor**: on the same kit, coupon estimated 7 g / measured 17 g; P2 plate estimated 43 g / measured 34 g — the walls of a Ø16 small peg eat ~67% of the section, a large hollow sphere ~20%, a 2.5 mm thin plate ~100%; **no single factor can fit all three**.
- `scripts/bake_project.py` — **mandatory before delivery**: bakes the pure-geometry 3MF into a "saved by the slicer itself" project file (adds `Metadata/project_settings.config` + gcode + thumbnails), also writing `close_fan_the_first_x_layers` / `curr_bed_type` / per-object brim, and only overwrites the original after read-back verification. Pitfalls and acceptance checklist in `references/delivery.md`.

## Hard-won pitfalls

Rendering and export traps are at the end of `references/printability-checklist.md`: two guaranteed matplotlib 3D traps (multiple collections without depth sorting, projecting before `view_init` double-projects), and trimesh `capsule()` not taking a `sections` parameter.

Color-split traps are in `references/split-to-print.md` (a pin fatter than the limb it crosses severs it; a pin hole buried inside a solid is a cavity; appendage parts must not penetrate the body; mirrored parts must reuse orientation).

Glue-free joint traps are in `references/snap-fit.md` (letting the female side yield = yielding it permanently; cutting the collar only halfway turns the socket wall into a hidden collar; the ball equator must sit behind the collar; an unburied pin root = boolean silently drops the connection).

Warping and stance traps are in `references/warp.md` (triage by "where it fails"; the `lift` criterion and the COM stance criterion; four geometric fixes; two silent traps — chamfer and buried section; Bambu parameter table; X2D chamber lid/front-door directions are opposite; **`--slice` without presets hangs forever, disguised as "GUI holds the lock"**).

Delivery and bake traps are in `references/delivery.md` (two 3MF layouts and false negatives; the three-step bake; seven parameter-level pitfalls, including "rejection disguised as a hang"; acceptance checklist).

Plus these general ones:

- **A solid base plate added "to merge parts into one object" bundles warping risk into the deal.** Winston v1's coupon put 5 collar sockets on a 102 × 28 × 2.5 mm plate; measured result: printed scrap. The plate's long edge lifted, the nozzle scraped it every pass, a full row of squashed-and-torn material lined the edge, and both Ø20 peg discs' rims lifted too. Measured: `span 102 mm / depth 6.0 mm → ratio 17` (gate threshold 12). The plate **wasn't load-bearing at all** — it existed only to make five Ø16×21 columns (aspect ratio 1.3:1, unpushable) into one object. Delete it: contact area 3484 → 1206 mm², span 102 → 14.8 mm, everything moves to `ok`. **Before doing anything, ask: is this base plate actually load-bearing?**
- **Measure warping with `lift = span²/depth`, not the ratio, and not dimensions alone.** Lift h ∝ ε·span²/depth — it grows with the **square** of span. The first criterion was `span/depth`, which flagged the Ø35×2.8 pupil disc as `redesign`, while the plate that actually failed at 102 mm was merely "over the line" — **a ratio criterion can't tell "one size smaller" from "an order of magnitude smaller"** (the pupil's real risk is (35/102)² = 1/11 of the plate's). False alarms cause pointless rework of good parts. Also add a floor: **any plate with `depth ≤ 4.5 mm` gets brim, always** — its own stiffness won't save it. **Don't estimate `depth` from the vertex bounding box**: a trimesh cylinder only has vertices on its end caps, so a Ø16×18.5 solid column gets estimated as a 0.6 mm sheet and misjudged as "soft". Use volume ÷ area: sheets yield plate thickness, solid columns yield column height — both extremes come out right.
- **Also ask "will it stand up?"**: `warp.py`'s `COM` = margin from center of mass to the ground outline edge; **negative = it tips over on its own**, and the slicer can't see it at all (brim was laid for the old pose; once it flips, the part is scrap). **Don't judge stability by contact area**: a cylinder lying down has line contact — area ≈ 0 yet perfectly stable; a barrel can have a huge contact patch yet rest on one edge. Winston's glue-free version caught two parts (horn COM −2.1 / ear fin −2.4), the glued version caught one more (horn with only **3 vertices** touching the plate); after re-posing: +2.8 / +1.9 / +4.5. The fix is always `splitter.rest_flat()` (searches the **convex-hull faces** for one that points down and keeps COM inside the outline); don't hand-tune angles.
- **Two rulers; mixing them grades bad parts as good (the most expensive lesson here)**: "does this pose have a face touching the plate" must use **`CONTACT_TOL = 0.10 mm`**; "is COM off-center" gets 0.6–0.8 mm. On the glued horn, that ring of vertices 0.55 mm off the plate — nowhere near touching — counted as **80 mm² of ground area** under `footprint()`'s default 0.8 mm tolerance — so the packer believed it "stood fine", `rest_flat` never fired, and **round one caught nothing**. The real number: at 0.10 mm tolerance its ground area is **0.07 mm²**. The same ruler must run through both the gate and the packer, or you get "the gate says it tips, the packer says it's fine" and everything deadlocks (exactly why the ear fin's first rebuild didn't move a millimeter). Details in `references/warp.md`.
- **Don't copy the solver into project scripts.** Winston's `snapkit_winston.py` carried its own copy of `lay_flat`; fixing the library copy had zero effect on the script (after the rebuild, two poses were unchanged, one debugging round burned). All `footprint / sit / lay_flat / upright` in project scripts must call `splitter`.
- **A chamfer must be cut, not unioned.** Union a taper ring under a cylinder and the cylinder's own full circular bottom face is still there — you did nothing (contact area won't change by one byte). The correct way: `outer_ring - inner_taper` gives you a cutter, then subtract it from the cylinder. `ptools.chamfered_base()` wraps this.
- **Weight must come from the slicer, not mesh volume × factor.** Same kit, measured: coupon mesh-estimated 7 g / slicer-measured **17 g** (2.4× off, the user caught it on the spot); P2 dark plate estimated 43 g / measured 34 g. Why: the Ø16 small peg's 2–3 wall loops + solid top/bottom eat ~67% of the section, large hollow sphere ~20%, 2.5 mm thin plate ~100%. Run `weigh_3mf.py` before reporting (seconds per plate with presets + sums gcode E values), and state the **preset basis** and density; `splitter.plastic_g` only goes in script self-tests, labeled `est.`.
- **The "3mf file configuration invalid, loading geometry only" popup must be baked away, not coached with "just click through it"**: official English text is "The 3mf is not from Bambu Lab, load geometry data only"; a forum moderator's words: "Consider it as 'information'" — it really is an **identity notice, not an error**. But that's true for "files you made for yourself"; for a file **delivered to a user to print**, it's pure noise: the user sees red text and comes asking, and all you can say is "just click through it". Root cause: no `Metadata/project_settings.config` in the file. **Hand-assembling that file is asking for trouble** (version strings, preset ids, 569 keys, inheritance chains); the right fix is to let the slicer write its own file (`--slice --export-3mf`, one call; archive members 4 → 17–20). **Anything you can do in one pass, don't leave to the user** — one extra slicer run buys out one round of "why is this popup back".
- **Project-style 3MFs make validation scripts silently produce false negatives (the sneakiest one)**: the slicer's `--export-3mf` output is a **project-style** layout — geometry lives in `3D/Objects/object_N.model`, the main model holds only `<component p:path="..."/>`, placement lives in `<build><item transform="...">` (parts are stored in **local coordinates**; z can be negative). A script reading only `3D/3dmodel.model` will: **read zero objects → gate prints "all clear" while checking nothing**; or read the parts without applying transforms → false "verts below the bed". **A false negative is more dangerous than a false positive — it makes you believe you validated.** `audit_3mf.py` / `warp.py` now read both layouts and apply the build transform as `v @ M[:3,:] + M[3,:]`.
- **The CLI does not resolve filament presets' `inherits`, and it only drops fields you don't look at**: loading only `Bambu PETG Basic @BBL X2D 0.4 nozzle.json` yields `filament_density: 0` / `total filament weight [g]: 0.00` in the gcode — the project shows **0 g**. Meanwhile **the fields that actually drive toolpaths pass through fine** (fan 60%, nozzle 250 ℃, flow 0.95), **and the fields you'd casually check are all correct — which is exactly why the hole is hard to spot**. Before slicing, write `filament_type` / `filament_density` explicitly into the preset copy.
- **Don't hand-write density; nearest definition wins and it isn't the category value**: `Bambu PETG Basic @base` = **1.25**, overriding `fdm_filament_pet`'s 1.27; `Bambu PLA Basic @base` = **1.26**, overriding `fdm_filament_pla`'s 1.24; `fdm_filament_common`'s 0 is a placeholder to skip. Hand-writing the category value 1.27 makes the delivered file's weight read **1.6%** higher than the slicer's — and that's the number the user uses to judge whether they have enough filament. Both `bake_project.py` / `weigh_3mf.py` have `resolve_filament()` / `resolve_density()` walking the chain.
- **`close_fan_the_first_x_layers` defaults to 1 — the #1 cause of "ruined bottoms"**: Bambu turns the fan on at layer 2 (measured `M106 S104`); the bottom face gets blown cold and shrinks before it has set. At 3, layers 1/2/3 run `S0` and layer 4 gets `S255`. In the GUI it hides under "Cooling → no fan for the first N layers"; **the default will never be right on its own** — pin it into the file at bake time.
- **The slicer's `auto_brim` and the warping gate are two different criteria with no overlap**: `auto_brim` asks "will the nozzle knock it loose"; `warp.py` asks about warping (`lift = span²/depth`). Measured on one plate: `06 ear fin`/`05 horn`/`07 arm` got automatic brim, while `04 pupil`, banded `brim` by the gate, **did not**. **Run both; whoever says brim, add brim** — automatic brim is not a substitute for the gate.
- **`--export-3mf` takes a filename, not a path**: the CLI appends it to `--outputdir`. Passing an absolute path → `<outputdir>/<abs path>` → `Unable to open the file ...tmp`.
- **Never `rmtree` the script's own cwd**: the subprocess `cwd=` points at a deleted inode; the slicer reports `Could not determine canonical path to application directory` / `setup params error`, and **the script file itself may get deleted too**. Use `/tmp/<something>` as the working directory.
- **XML metadata must be inserted after a complete tag**: replacing only the regex hit produces `<metadata key="name" value="x" <metadata .../>` — invalid XML. The slicer responds by **silently dropping all object names**, and the delivered file shows `Object_3`/`Object_4` with no relation to your `04 pupil`. Replace **the complete tag** + add an `ET.fromstring()` guard; injection must also be **idempotent** (the delivered file is project-style, so "bake again" is a routine operation).
- **Bed type is an enum index, not a name**: the binary string-table order (0-based) is `Default → Cool Plate → Engineering Plate → High Temp Plate → Textured PEI Plate → Supertack Plate`, and configs store that index. To confirm a setting, the hardest evidence is **edit a machine preset copy → check the gcode's `M190`** (measured: Textured PEI + PETG Basic → `M190 S70`). ⚠️ **Bed temperature is not in the machine preset chain; it's in the filament chain** (`textured_plate_temp`, PETG Basic 70 / PLA Basic 55): when the CLI fails to resolve `inherits`, it falls back to a hardcoded **45 ℃** — our first delivery file was `M190 S45`, **25 ℃ off, PETG guaranteed not to stick**, while the "toolpath-driving" nozzle temperature 250 / fan 60% passed through perfectly, making it easy to miss. `bake_project.py` now **flattens all three chains** (machine / process / filament) before handing them to the slicer. The preset default is Cool Plate 35 ℃ — **changing filament without changing the plate type throws the work away**.
- **When the slicer "refuses" a job it doesn't fail — it disguises itself as a hang**: plate/filament mismatch (e.g. PETG on Cool Plate) makes it write the reason into **`result.json`** in the working directory (`error_string` + `return_code: -61`), **and then the process doesn't exit**. From outside, "refused" and "stuck" look identical, so it's easy to go hunting elsewhere for a timeout. The criterion must be **`return_code`, not the truthiness of `error_string`** — **on success that field is also `"Success."`** (the first version did this and reported every successful slice as `refused: Success.`). And `slice.log` is always **one line** (`Initializing StaticPrintConfigs`, 92 bytes), **identical for success and failure**, useless for diagnosis. `presets.read_result_error()` reads `result.json`; `weigh_3mf.py` / `bake_project.py` poll it every round: unsupported plate drops from a 180 s timeout to an **error in 1.2 s**.
- **Coupons / test parts are always single-color**, don't give them two slots "to look nice". Measured: writing the fit coupon as "red = socket / blue = pin" made the X2D refuse to slice with **"printing high-temperature and low-temperature materials simultaneously may clog the nozzle or damage the printer"** — two slots trigger the dual-nozzle hot/cold material check, and the colors are pointless anyway (shape already separates socket from pin); single-color also lets you print from scrap. **A mixed-color single plate is not color-split either**: color-split's wins are zero purge / zero wipe tower / per-part optimal orientation; three colors on one bed loses the first two. The round-trip check is `slots_used = {1}`.
- **`<basematerials>` does nothing in Bambu Studio**, and it **disguises itself as success**: the 3MF is valid, geometry loads fine, only all colors are lost and object names degrade to `Object_N`. The only thing that works is `extruder` in `Metadata/model_settings.config` (= filament slot number). **Don't embed `project_settings.config`** — Bambu drops it and keeps its own presets.
- **Accept with the slicer's own engine before delivery; don't stop at zip/XML checks**:
  `BambuStudio --info x.3mf` (check `manifold` and `number_of_parts`; expect 1 connected body per object),
  `BambuStudio --export-3mf rt.3mf --outputdir /tmp/out x.3mf`, then read the config back and verify names and slots.
  The CLI is a GUI program and never exits; macOS has no `timeout` → background start + `sleep` + `kill`.
  These two subcommands **need no presets**; **`--slice` does** (missing `--load-settings` / `--load-filaments` hangs forever at `Initializing StaticPrintConfigs`; don't misdiagnose as the GUI holding a lock).
- **Grade markers on parts go as through-holes, not bumps**: same-color bumps share the surface normal of the plate = same brightness; unreadable top-down or in hand.
- **"Is the part one connected solid" cannot be judged with `trimesh.load()`**: the STL/3MF load paths merge vertices and drop degenerate faces, **and the repair itself wrecks edge pairing on good parts** — `is_watertight` goes False, `split()` invents dozens of zero-volume "fragments". Same kit, measured: the load path called 8 of 10 parts broken; rebuilt from the files' own indices, all 10 were watertight, one solid each, and the slicer engine judged `manifold = yes`. To check, parse the XML yourself and build `Trimesh(process=False)` (`audit_3mf.py`), and take `BambuStudio --info`'s `number_of_parts` as final.
- **Pin end face exactly coplanar with the host = silent fragments**. Invisible at the `.stl` level, invisible to in-process connectivity checks, **only the slicer's `number_of_parts` flags it** (horn reported 5). Anywhere "a pin inserts into a boss/collar", the pin must extend **2–3 mm further into the host** to create real overlap.
- **trimesh's `cone()` has its base at z=0 and apex at +h** (cylinder / capsule are centered). Using it directly places the cone "growing h from `at`", **silently detaching it from the part it should join**. `ptools.cn()` already adds `-h/2`; don't bypass it for `trimesh.creation.cone`.
- **Two solids sharing exactly coincident coordinates: the union is "two solids sharing one face"**, and booleans silently drop that connection.
  Wherever "a male feature grows out of a host's surface" (pins, posts, bosses), the root must be **buried an extra 2 mm**.
- **Don't check connectivity by shared vertex indices**: near-duplicate vertices at boolean seams produce false floating-island reports.
  Weld by rounded coordinates, then count (`splitter.n_components` / `n_components` in scripts), or install scipy and use trimesh's graph algorithms.
- **matplotlib's default font has no CJK**; Chinese labels turn into tofu boxes. `preview.py` already sets PingFang SC / Hiragino Sans GB candidates in `rcParams["font.family"]`; do the same for your own annotation plots. **Don't hang `Poly3DCollection` on a 2D `Axes` for annotation diagrams** (`Axes` has no `get_proj`) — project to (x, z) and use a 2D `PolyCollection`, depth-sorted, far faces first.
